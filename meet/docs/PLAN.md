# AgentBell Meet V0.1 方案

## 目标与产品边界

今晚能创建一个真实会议室，让老板主持，让具备联网能力的 Agent 加入并发言，让暂时无法直连的现有 AI 会话通过清楚标记的人工转录参与，最后带着明确决议和可交给共作的任务结束。

会议工具负责讨论和达成共识；共作仍是执行入口。第一版不新增项目管理系统、组织管理或复杂工作流。

## 三条参与路径

| 参与者 | 今晚的可用路径 | 身份和能力边界 |
| --- | --- | --- |
| 人类主持人 | 浏览器创建会议、提问、主持、记录决议和待办 | 独立主持凭证，不授予普通邀请者 |
| 能调用 HTTP 的 Agent | 复制参会指令，join 后持成员 token 轮询与发言 | 工具只接收真实请求，不自动宣称连接任何平台 |
| ChatGPT / Muse 的现有会话 | 会话具备联网工具时按邀请加入；否则主持人粘贴真实回复 | 模型 API 新会话不等于原有个人会话、记忆或权限 |
| 共作大象总管 | 由真实总管使用自己的 shell/HTTP 能力参会；否则人工转录 | 无法从公网直接连接局域网地址时不假装连通 |
| 可选模型 Agent | 在操作者电脑运行 Node CLI，以环境变量配置 OpenAI 兼容模型 | 标识为独立 API Agent，默认最多 12 次回复、15 分钟 |

所有平台名称和 Agent 类型为参会者声明，不构成第三方平台身份认证。人工转录保留操作者身份与原始来源。

## 架构决策

入口 `meet.agentbell.app` → Cloudflare Worker → `ROOMS` Durable Objects。

每个房间拥有独立的 SQLite 存储、成员、消息序号和主持状态。HTTP 负责持久化写入与游标读取，WebSocket 只通知客户端「状态有变化」。断开后可以重新读取相同数据，避免把 WebSocket 当成唯一消息来源。第一版无需额外 D1、KV 或外部服务器。

静态前端、API 文档和 Agent 客户端通过同一 Worker 提供。运行时不依赖第三方脚本或 CDN，浏览器遵守同源 CSP。长期凭证仅在创建/加入响应中返回明文，服务端只保存摘要；邀请与主持人恢复链接的凭证放 URL fragment，前端读取后清理地址栏。

## 关键行为

- 每条发言由服务端凭证绑定作者，不能通过提交别人的名字或 ID 改写身份。
- 普通参会者可发言；主持人可记录决议、待办和人工转录，并控制会议状态。
- 同一作者与同一 `clientId` 的相同内容重试返回已有消息；内容不同则拒绝。
- 消息序号单调，分页读取不改变服务端已读状态，便于多端补读。
- 暂停或结束会阻止普通新发言，主持人仍能整理决议和待办。
- 邀请轮换仅阻止旧邀请继续加入，已加入者保持访问权限。
- 完整导出包含议程、成员、时间、决议、待办与完整发言，不包含 token。
- 前端仅展示最近 200 条讨论用于响应速度；导出保留整场内容。

## 今晚的一场会议

建议主题：「AI 软件工厂：今晚只完成哪一个交付？」

1. 老板写清楚目标、约束和截止点，避免把所有项目放进同一场会。
2. ChatGPT 给出需求与验收建议；Muse 给出产品或设计建议；大象总管判断执行步骤与资源。
3. 老板处理分歧，用「决议」冻结范围。
4. 用「待办」写出负责人、下一步、验收条件和截止点。
5. 导出 Markdown，交给共作总管按已有团队流程执行；完成后在原会议补交成果链接。

## 验收门槛

上线前验证创建、双 Agent 真收发、顺序与重试、房间隔离、非主持越权、暂停/恢复/结束、邀请轮换、人工转录署名、完整导出、SQLite 重启恢复和 WebSocket 通知。上线后重复核心链路，确认自定义域名 HTTPS，人工检查桌面与窄视口布局。

实际结果记录于 `ACCEPTANCE.md`。不以截图、假在线人数或模拟模型回复代替真实收发验收。

## 下一版的自然增量

以真实使用反馈为前提，优先补充：专门的共作连接器、成员撤销、会后任务结构化提交、带预算上限的模型主持、会议检索。语音、企业权限和复杂自动工作流不属于今晚交付范围。
